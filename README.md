
# 🏛️ Портал участковых уполномоченных полиции

**Информационная система для автоматизации обработки обращений граждан, организации работы участковых уполномоченных полиции и контроля исполнения обращений.**

Портал представляет собой веб-приложение, предназначенное для организации взаимодействия граждан с участковыми уполномоченными полиции, автоматизации рабочих процессов и повышения эффективности рассмотрения обращений.

Система объединяет инструменты регистрации обращений, территориального распределения, управления исполнением, согласования ответов и аналитического контроля деятельности подразделений.

## 🎯 О проекте

«Портал участковых» — информационная система, разработанная для автоматизации процессов взаимодействия граждан с участковыми уполномоченными полиции.

Основная задача проекта — оптимизация работы с обращениями граждан, автоматизация распределения заявок, обеспечение прозрачности процесса их рассмотрения и повышение эффективности контроля за исполнением.

В основе системы лежит разграничение функциональных возможностей в зависимости от должностной роли пользователя и последовательная маршрутизация обращений между ответственными сотрудниками.

Портал ориентирован на территориальную структуру подразделений полиции города Нижнего Новгорода.

### Основные задачи

- Организация электронного приёма обращений граждан.
- Автоматизация распределения обращений по территориальным участкам.
- Назначение ответственных сотрудников.
- Организация многоуровневого согласования ответов.
- Контроль сроков рассмотрения обращений.
- Ведение истории действий по каждому обращению.
- Формирование аналитической отчётности.
- Предоставление справочной информации об участковых пунктах и отделах полиции.

## 👥 Роли пользователей

В системе предусмотрено четыре категории пользователей.

| Роль             | Основные возможности                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Гражданин        | Создание обращений, просмотр собственных обращений, оценка качества рассмотрения                                                            |
| Участковый       | Просмотр назначенных обращений, принятие их в работу, подготовка ответов                                                                    |
| Начальник отдела | Контроль обращений своего отдела, согласование ответов, возврат на доработку, просмотр статистики                                           |
| Руководитель     | Управление обращениями, назначение исполнителей, финальное согласование, управление справочниками и публикациями, просмотр общей статистики |

### Гражданин

Личный кабинет гражданина позволяет создавать электронные обращения, отслеживать ход их рассмотрения и просматривать подготовленные ответы.

После завершения рассмотрения гражданин может оставить оценку качества работы.

### Участковый уполномоченный

Рабочий кабинет участкового предназначен для обработки назначенных обращений.

Сотрудник может принимать обращения в работу, изучать их содержание, готовить проекты ответов и передавать их на согласование начальнику отдела.

### Начальник отдела

Начальник отдела осуществляет контроль обращений, относящихся к его подразделению.

Основные функции:

- Просмотр обращений своего отдела.
- Контроль хода рассмотрения.
- Проверка подготовленных ответов.
- Согласование ответов и передача руководителю.
- Возврат ответов исполнителю на доработку.
- Просмотр статистических показателей своего отдела.

### Руководитель

Руководитель обладает полномочиями по управлению работой системы на уровне всего подразделения.

Основные функции:

- Просмотр всех обращений.
- Назначение ответственных участковых.
- Контроль исполнения.
- Финальное согласование ответов.
- Возврат ответов на доработку.
- Управление территориальным справочником.
- Привязка адресов домов к участкам.
- Управление информационными публикациями.
- Просмотр общей статистики.
- Экспорт реестра обращений.

## 🔄 Жизненный цикл обращения

Одной из ключевых особенностей проекта является реализация последовательного процесса обработки обращений с участием нескольких должностных лиц.

### Этапы обработки

**1. Регистрация обращения**

Гражданин заполняет форму, указывает категорию, тему, адрес и содержание обращения. При необходимости прикладывает дополнительные документы.

**2. Определение территориальной принадлежности**

Система проверяет адрес по справочнику привязки домов к участкам.

Если соответствие найдено, обращение получает назначенного исполнителя. Если нет — передаётся на ручное распределение.

**3. Назначение исполнителя**

Руководитель определяет ответственного участкового для обращений, требующих ручного назначения.

**4. Рассмотрение обращения**

Участковый принимает обращение в работу, изучает обстоятельства и формирует проект ответа.

**5. Согласование начальником отдела**

Подготовленный ответ передаётся начальнику соответствующего отдела.

Начальник может согласовать ответ либо вернуть его исполнителю на доработку с указанием причины.

**6. Финальное согласование**

После согласования начальником отдела ответ поступает руководителю.

Руководитель проверяет результат и принимает окончательное решение.

**7. Завершение рассмотрения**

После финального согласования обращение получает статус «Ответ направлен».

Гражданину становится доступен результат рассмотрения, после чего он может оценить качество работы.

### Схема маршрутизации

```
                 ГРАЖДАНИН
                     |
                     v
             Регистрация обращения
                     |
                     v
           Определение участка по адресу
                     |
              +------+------+
              |             |
          Найдено        Не найдено
              |             |
              v             v
       Автоназначение    Ручное назначение
              |             |
              +------+------+
                     |
                     v
             УЧАСТКОВЫЙ
                     |
               Принятие в работу
                     |
                     v
             Подготовка ответа
                     |
                     v
          НАЧАЛЬНИК ОТДЕЛА
                     |
              +------+------+
              |             |
         Согласование    Доработка
              |             |
              v             +----> Участковый
           РУКОВОДИТЕЛЬ
              |
        +-----+------+
        |            |
   Согласование   Доработка
        |            |
        v            +----> Участковый
  ОТВЕТ НАПРАВЛЕН
        |
        v
    ЗАВЕРШЕНИЕ
```

### Статусы обращений

| Статус                              | Описание                                    |
| ----------------------------------- | ------------------------------------------- |
| Ручное назначение                   | Обращение ожидает определения исполнителя   |
| Назначено                           | Обращение закреплено за участковым          |
| В работе                            | Участковый рассматривает обращение          |
| На согласовании у начальника отдела | Проект ответа передан начальнику отдела     |
| На согласовании у руководителя      | Ответ прошёл согласование начальника отдела |
| Ответ направлен                     | Рассмотрение завершено                      |

Каждое значимое действие фиксируется в истории обращения с указанием события и времени его выполнения.

## 🧩 Модули системы

### Личный кабинет

Основной рабочий раздел портала. Содержит список обращений, доступных пользователю в соответствии с его ролью.

Предусмотрены:

- Поиск по теме и адресу.
- Фильтрация по статусам.
- Постраничный вывод.
- Индикация просроченных обращений.
- Предупреждение о приближении срока исполнения.

### Карточка обращения

Содержит полную информацию об обращении:

- Регистрационный номер.
- Данные заявителя.
- Категория и тема.
- Адрес события.
- Текст обращения.
- Прикреплённые материалы.
- Текущий статус.
- Срок исполнения.
- Проект ответа.
- История обработки.

Набор доступных действий зависит от роли пользователя и текущего этапа рассмотрения.

### Территориальный справочник

Справочник объединяет сведения об участковых пунктах и отделах полиции.

Для удобства навигации объекты сгруппированы по районам. Предусмотрено отображение расположения пунктов на интерактивной карте.

Руководителю доступно управление привязкой адресов домов к территориальным участкам.

### Статистический модуль

Предназначен для анализа поступающих обращений и контроля эффективности работы.

Реализованы графики, сводные показатели и табличные отчёты. Для удобства предусмотрены фильтры по периоду и функция печати статистических материалов.

### Информационный модуль

Предназначен для публикации новостей, сообщений и отчётов участковых подразделений.

## 📊 Статистика и аналитика

Статистический модуль предоставляет инструменты для оценки текущей нагрузки и результатов работы подразделений.

### Основные аналитические показатели

- Всего зарегистрировано обращений.
- Количество закрытых обращений.
- Количество активных обращений.
- Количество просроченных обращений.
- Количество обращений на отдельных этапах согласования.
- Доля обращений, завершённых в установленный срок.
- Средняя продолжительность рассмотрения.

### Визуализация данных

В системе используются следующие виды графиков:

- Распределение обращений по категориям.
- Распределение обращений по статусам.
- Динамика поступления обращений за последние 12 месяцев.

### Периоды анализа

Доступны следующие варианты фильтрации:

- За всё время.
- Текущий месяц.
- Текущий квартал.
- Текущий год.
- Произвольный диапазон дат.

Для руководителя доступна общая статистика подразделения, начальник отдела видит показатели в пределах своего отдела.

### Экспорт

Реализована выгрузка реестра обращений в CSV.

Выгрузка включает основные сведения об обращениях, данные исполнителей, статусы, сроки, оценки и последовательность событий маршрута обработки.

## 🛠️ Технологический стек

### Backend

- **PHP 8.1+** — серверная логика приложения.
- **PDO** — взаимодействие с базой данных и выполнение SQL-запросов.

### Database

- **MariaDB** — основная система управления базами данных.
- **Совместимые SQL-СУБД** — возможность использования других совместимых систем управления базами данных.
- **InnoDB** — механизм хранения данных.
- **UTF-8 / utf8mb4** — поддержка русского языка и Unicode.

### Frontend

- **HTML5** — структура страниц.
- **CSS3** — оформление интерфейса.
- **JavaScript** — клиентская логика и интерактивные элементы.

### Внешние библиотеки и сервисы

- **Chart.js** — построение статистических графиков.
- **Leaflet** — интерактивная карта.
- **OpenStreetMap** — картографические данные.
- **Photon / Komoot** — адресный поиск и подсказки.

## ⚙️ Установка и запуск

### Требования

Для развёртывания приложения необходимы:

- PHP версии 8.1 или выше.
- MariaDB.
- Веб-сервер Apache.
- Расширения PHP:
    - PDO.
    - PDO MySQL.
    - Fileinfo.
    - Mbstring.
    - Session.

### 1. Размещение проекта

Разместите файлы проекта в каталоге веб-сервера, обеспечив корректную настройку доступа к приложению.

### 2. Подготовка базы данных

Подготовьте базу данных MariaDB для работы приложения.

### 3. Настройка подключения

Откройте файл `config.php` и укажите параметры подключения к используемой базе данных.

### 4. Запуск

После настройки веб-сервера и подключения к базе данных откройте адрес развёрнутого приложения в браузере.

## 🛡️ Особенности реализации

При разработке предусмотрены следующие механизмы:

- Использование подготовленных SQL-запросов PDO.
- Экранирование пользовательского вывода.
- CSRF-защита операций изменения данных.
- Разграничение доступа на основе пользовательских ролей.
- Проверка принадлежности обращения пользователю.
- Проверка прав доступа к прикреплённым материалам.
- Ограничение количества обращений от одного гражданина — не более трёх в сутки.
- Ограничение частоты неудачных попыток входа.
